# Release Notes — QA Automation Update

**Дата выпуска:** 28 июля 2026  
**Тип изменений:** тестовая автоматизация и расширение покрытия

## Кратко о релизе

Набор автотестов расширен с **25 до 31 сценария**. Добавлены проверки безопасности ролевого доступа, завершения пользовательской сессии, негативных сценариев создания КП и сохранения данных профиля.

Изменения относятся только к тестовой инфраструктуре и **не затрагивают продуктовый код приложения**.

| Метрика | Было | Стало | Изменение |
|---|---:|---:|---:|
| Всего автотестов | 25 | 31 | +6 |
| UI-тесты | 17 | 22 | +5 |
| API-тесты | 8 | 9 | +1 |

## Что добавлено

### Авторизация и безопасность

- Проверен выход пользователя из системы и запрет повторного открытия защищённой страницы.
- Проверён запрет прямого доступа менеджера к административным разделам, даже если URL введён вручную.

### Коммерческие предложения

- Добавлена UI-проверка обязательных полей формы создания КП.
- Добавлена проверка отмены создания: модальное окно закрывается, новое КП не появляется в списке.
- Добавлена API-проверка: КП с пустым названием не создаётся.

### Профиль пользователя

- Добавлена проверка отображения сохранённых настроек менеджера и контактов после перезагрузки страницы.
- Существующий API-сценарий удаления аватара и подписи расширен проверкой, что ссылки на удалённые файлы больше не возвращаются.

## Технические изменения

- Новые проверки распределены по существующим spec-файлам согласно функциональным областям, без создания дублирующих тестовых наборов.
- Селекторы ошибок формы создания КП вынесены в `CreateProposalComponent`:
  - `nameError`;
  - `calculatorError`.
- README синхронизирован с фактическим количеством и составом автотестов.
- Для новых сценариев не добавлялись пользовательские таймауты или отдельная обработка `429`.

## Польза для проекта

- Снижена вероятность пропустить нарушение ролевого доступа.
- Расширено негативное покрытие создания КП.
- Подтверждается корректное завершение пользовательской сессии.
- Усилена проверка сохранения и удаления пользовательских данных.
- Структура тестов остаётся понятной: сценарии находятся рядом с тестами соответствующей функциональности.
